# HTML 正文空白字符问题与修复基线


## 确认的内容差异

| 输入 | Chrome 实际 innerText | 阅读器实际文本节点 |
| --- | --- | --- |
| pre-line: 第一行 + 两个 LF + 第三行 | 保留两个 LF | 只剩一个 LF，空行丢失 |
| normal: 甲 + 两个 U+00A0 + 乙 | 保留两个不换行空格 | 只剩一个 U+0020，字符和断行语义均改变 |
| pre-line: 甲 + 两个 U+00A0 + 乙 | 保留两个不换行空格 | 阅读器只剩一个 U+0020 |

三项均已通过本机 Chrome headless `--dump-dom` 独立运行页面脚本、读取 innerText 确认。阅读器通过 `renderHtmlDomTree` 递归读取实际文本节点，三个最小回归用例均在当前基线失败，不是函数不存在或环境失败。

复现：`node --test tests/html-whitespace-content.test.js`。

疑似直接原因：`normalizeVisibleText` 的 `/\s+/` 和 `/[^\S\r\n]+/` 把不属于普通可折叠空格的 Unicode 字符合并；pre-line 分支还用 `/\n{2,}/` 删除空行。不能只修这两行就宣布完成，应继续检查上下游 trim、跨内联节点、HTML 输入换行归一化和微信 WXML 文本输出。

## 本轮验证路径（已执行，真机除外）

1. 持久化独立浏览器对照，补正常/pre-line/pre/pre-wrap、CRLF、制表符、实体与Unicode空格组合；核对正文和实际换行，不只看字符串。
2. 寻找具有来源与许可的公开 HTML/CSS 空白处理样本，至少2–3份并记录文件指纹。
3. 最小修复后检查常见文章、复制文本、表格、按钮、计算器，以及跨节点空格；保留真正可折叠空白的折叠行为。
4. 在微信模拟器检查实际文字和布局；真机仍需独立证据。建立HTML能力档案，再进行新版本GitHub及开发版交付。

该问题没有混入 v1.4.48 的CDR修复和回执提交。
